# ISA 测试数据说明：`hex_data/data_*.hex` 与 `mem_init.hex` 的排列关系

## 概述

ISA 测试的输入数据分两个层次：

1. **`hex_data/data_*.hex`**：4096 个小文件，每个文件存 4 个 fp32 值，对应 5 维张量的一个索引组合。
2. **`build/mem_init.hex`**：仿真器直接加载的内存初始化文件，由上述 4096 个文件按固定规则拼装而成，加载到地址 `0x40000000`（acc_addr）。

两者由 `run_test.sh` 每次运行时同步生成，始终保持一致。

---

## 第一层：`hex_data/data_*.hex`

### 文件命名

```
data_{i0}_{i1}_{i2}_{i3}_{i4}.hex
```

5 维索引各维度取值范围：

| 维度 | 长度 | 取值     |
|------|------|----------|
| i0   | 4    | 0 ~ 3    |
| i1   | 4    | 0 ~ 3    |
| i2   | 8    | 0 ~ 7    |
| i3   | 8    | 0 ~ 7    |
| i4   | 4    | 0 ~ 3    |

总文件数：4 × 4 × 8 × 8 × 4 = **4096 个**


### 脉动阵列层次结构与索引含义

> 原始描述：脉动阵列的结构首先是4\*4个32\*32，每个32\*32里面是 8\*8个4\*4，每个4\*4横向每一行输出一个acc reg，所以 idx0表示每个32\*32的行坐标，idx1对应列坐标，idx2对应4\*4的行坐标，idx3对应列坐标，idx4对应4\*4的行坐标。

脉动阵列由三层嵌套结构组成，5 维索引分别对应各层的坐标：

```
┌─────────────────────────────────────────────────────────┐
│          顶层：4 × 4 个 32×32 块                         │
│                                                         │
│   idx0 = 行 (0~3)    idx1 = 列 (0~3)                   │
│                                                         │
│   (0,0) (0,1) (0,2) (0,3)                              │
│   (1,0) (1,1) (1,2) (1,3)                              │
│   (2,0) (2,1) (2,2) (2,3)                              │
│   (3,0) (3,1) (3,2) (3,3)                              │
│                                                         │
│   ┌─────────────────────────────────────────────┐       │
│   │   每个 32×32 块：8 × 8 个 4×4 cell           │       │
│   │                                             │       │
│   │   idx2 = 行 (0~7)    idx3 = 列 (0~7)       │       │
│   │                                             │       │
│   │   (0,0)(0,1)...(0,7)                        │       │
│   │   (1,0)(1,1)...(1,7)                        │       │
│   │    ...                                      │       │
│   │   (7,0)(7,1)...(7,7)                        │       │
│   │                                             │       │
│   │   ┌───────────────────────────────────┐     │       │
│   │   │   每个 4×4 cell                   │     │       │
│   │   │                                   │     │       │
│   │   │   idx4 = 行 (0~3)                │     │       │
│   │   │   每行横向有 4 列 = word 0~3      │     │       │
│   │   │                                   │     │       │
│   │   │   row0: [w0][w1][w2][w3] → acc   │     │       │
│   │   │   row1: [w0][w1][w2][w3] → acc   │     │       │
│   │   │   row2: [w0][w1][w2][w3] → acc   │     │       │
│   │   │   row3: [w0][w1][w2][w3] → acc   │     │       │
│   │   │                                   │     │       │
│   │   │   每行输出 1 个 acc reg            │     │       │
│   │   └───────────────────────────────────┘     │       │
│   └─────────────────────────────────────────────┘       │
└─────────────────────────────────────────────────────────┘
```

因此每个 `data_{i0}_{i1}_{i2}_{i3}_{i4}.hex` 文件代表：
- 位于顶层第 `(i0, i1)` 个 32×32 块
- 该块内第 `(i2, i3)` 个 4×4 cell
- 该 cell 第 `i4` 行的 **4 个 fp32 值**（对应 4 列 word 0~3）

总 acc reg 数 = 4 × 4 × 8 × 8 × 4 = **4096 个**，每个 acc reg 含 **4 个 fp32**。


### 文件内容

每个文件包含 **4 行**，每行一个 32-bit hex 值（IEEE 754 fp32，大端格式），对应 4 个浮点数：

```
# data_0_0_0_0_0.hex 示例（seed=42）
BE80788E    ← 第 1 个 fp32（word 0）
3F66C407    ← 第 2 个 fp32（word 1）
3EED8FD2    ← 第 3 个 fp32（word 2）
3E4A0D76    ← 第 4 个 fp32（word 3）
```

### 数据生成规则

由 `generate_tensor_data.py` 生成，随机模式下每个文件的种子独立计算：

```
flat_index = i0*(4*8*8*4) + i1*(8*8*4) + i2*(8*4) + i3*4 + i4
per_file_seed = base_seed + flat_index
np.random.seed(per_file_seed)
values = np.random.uniform(-1.0, 1.0, 4).astype(np.float32)
```

因此：
- 同一 `--seed` → 所有文件数据完全确定（可复现）
- 不同 `--seed` → 所有文件数据全部变化

## 第二层：`build/mem_init.hex`

### 整体结构

`mem_init.hex` 分为 **4 个 segment**，每个 segment 对应所有文件中同一位置（word）的 fp32 值：

```
@00000000   ← segment 0：所有 4096 个文件的 word 0（每文件第 1 行）
...（4096 个 words，每 32 个 words 为一行）

@00004000   ← segment 1：所有 4096 个文件的 word 1（每文件第 2 行）
...

@00008000   ← segment 2：所有 4096 个文件的 word 2（每文件第 3 行）
...

@0000C000   ← segment 3：所有 4096 个文件的 word 3（每文件第 4 行）
...
```

每个 segment 起始地址计算：

```
segment_w 的地址偏移 = w × 4096 × 4 bytes = w × 0x4000
```

总大小：4 segments × 4096 words × 4 bytes = **65536 bytes = 64 KB**

### Segment 内部的排列顺序

每个 segment 内，4096 个 words 按以下 5 重循环顺序排列（**i0 为最外层，i3 为最内层**）：

```
for i0 in 3..0 (倒序, 最外层，变化最慢):
  for i2 in 7..0 (倒序):
    for i4 in 3..0 (倒序):
      for i1 in 0..3:
        for i3 in 0..7 (最内层，变化最快):
          取 data_{i0}_{i1}_{i2}_{i3}_{i4}.hex 的第 w 行
```

> **注意**：i0、i2、i4 是**倒序**遍历的；i1、i3 是正序遍历的。

### 示例：@00004000 第一个 word

segment 1（word=1）第一个值对应循环中第一次迭代：
- i0=3, i2=7, i4=3, i1=0, i3=0
- 读取 `data_3_0_7_0_3.hex` 的第 2 行

```bash
$ sed -n '2p' hex_data/data_3_0_7_0_3.hex
BCE78205

$ awk '/^@00004000/{found=1; next} found{print $1; exit}' build/mem_init.hex
BCE78205   # 与上面一致 ✓
```

## 仿真器中的内存映射

`mem_init.hex` 加载到仿真器地址 `0x40000000`（acc_addr），固件通过 `ts.pop` 指令按地址读取：

```
物理地址 = 0x40000000 + segment_offset + word_index * 4

其中 segment_offset = w * 0x4000 * 4 = w * 0x10000
```

## `build/dtcm.hex`

### 来源

`dtcm.hex` 是仿真**结束后**由仿真器 dump 出的输出文件，不是输入数据。  
仿真器调用 `dump_dtcm_complete()` 将 DTCM 内存（`0xA0000000`）前 **0x200 字节（512 bytes）** 原样导出。

### 格式

起始地址 `@a0000000`，每行 4 words（16 bytes），共 32 行。

### DTCM 内存布局

| 偏移 | 地址 | 大小 | 内容 |
|------|------|------|------|
| `+0x0000` | `0xA0000000` | 0x100 | **CMD_FIFO**（仿真器在启动时写入） |
| `+0x0100` | `0xA0000100` | 0x100 | **测试参数**（从 ELF `.data` 段加载） |

### CMD_FIFO（`+0x0000`，前 4 words）

```
偏移   值           含义
+0x00  00000001    STATUS = 1（ready）
+0x04  800001b4    KERNEL_PTR（固件 kernel 入口地址）
+0x08  a0000100    PARAM_PTR（指向参数区）
+0x0C  a000e000    STACK_PTR（栈顶地址）
+0x10  00001000    STACK_SIZE（4096 bytes）
```

### 参数区（`+0x0100`，第 18 行）

```
偏移       值           含义
+0x000  00004000    acc_addr（输入张量基地址，加载 mem_init.hex 的起始位置）
+0x004  00000000    mode（0 = POP 模式）
+0x008  00000004    max_dtype（4 = fp32）
+0x00C  00000004    min_dtype（4 = fp32）
```

> `acc_addr = 0x00004000` 是相对于 ITCM 基地址 `0x40000000` 的偏移，  
> 仿真器中实际物理地址为 `0x40000000 + 0x00004000 = 0x40004000`。  
> （注：不同配置下 acc_addr 值可能不同，以实际 dtcm.hex 为准。）

### 用途

RTL 仿真可直接加载 `dtcm.hex` 初始化 DTCM，省去手动配置 CMD_FIFO 和参数的步骤，与 `mem_init.hex`（输入张量）、`itcm.hex`（固件）配合完成完整的 RTL 验证。

## 数据流总结

```
generate_tensor_data.py --seed N
        │
        ▼
hex_data/data_{i0}_{i1}_{i2}_{i3}_{i4}.hex   (4096 个文件，每文件 4 行)
        │
        │  按 (i0↓→i2↓→i4↓→i1→i3) × (word 0~3) 拼装
        ▼
build/mem_init.hex   (4 segments @ 0x0000 / 0x4000 / 0x8000 / 0xC000)
        │
        │  加载到仿真器 acc_addr = 0x40000000
        ▼
tensorstore_isa_test_rtl_sim_v2 → ts.pop 指令读取 → 写入张量寄存器 tr0~tr11
```

## 重新生成数据

```bash
# 使用默认 seed=42
bash run_test.sh

# 使用自定义 seed
bash run_test.sh --seed 1234

# 仅生成数据，不运行仿真
bash run_test.sh --gen-data --seed 1234
```

每次运行都会同步重新生成 `hex_data/` 和 `build/mem_init.hex`，两者始终对应同一个 seed。
